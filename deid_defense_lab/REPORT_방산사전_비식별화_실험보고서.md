## 1. 배경 및 목적

판결문 등 비정형 문서의 비식별화는 이름·주소 같은 일반 개인식별정보(PII)는 비교적 잘 다루지만,
방산기술 유출·군사기밀 사건처럼 **도메인 특화 정보**(기술명, 반출 수법, 수령처, 과제코드 등)는
기존 범용 모델·기준이 충분히 다루지 못할 수 있다. 본 실험은 **방산·안보수사 사전**을
최소 단위(사전 항목 1개)로 확장하며, 사전 규모(1만~10만 항목)가
(a) 처리 속도, (b) 메모리, (c) 저전력 CPU 환경에서의 실행 가능성, (d) 탐지 품질에 미치는 영향을 측정한다.

## 2. 선행 연구·기준 확인 결과

> 아래는 2026-10-02 시점 웹 검색으로 확인한 범위이며, 비공개·내부 자료는 확인하지 못했다.

| 구분 | 확인 내용 | 시사점 |
|---|---|---|
| SNU Thunder-DeID (서울대 이재진 교수팀, 2025) | 형사 판결문 4,500건에서 약 27,000개 개체를 수작업 라벨링, **595종** PII 유형 체계 구축. DeBERTa-v3 기반(370M 등). 대상 여부 판별 99% 이상, 세부 유형 분류 89% 이상 보고. 모델·데이터셋·코드 공개. EMNLP 2025 Findings 수록 | 비식별화 **기준(baseline)** 으로 사용 가능 |
| Thunder-DeID+ (2026-09 발표) | 한국어 경계 인식 토크나이저 + 3단계 분류체계. 개인정보 경계 분리 70.8%→99.7% 보도 | 후속 버전과의 비교 필요 |
| K-LegalDeID / KLUEBERT-CRF (고려대 정연돈 교수팀, EACL 2026) | 39개 법률 분야 2,000건 판결문 + SNS 대화 등으로 약 100만 건 규모 학습데이터 구성, CRF 결합 | 또 다른 비교군 |
| **방산·안보수사 특화 사전으로 위 모델을 개선한 실험** | **이번 검색에서 공개된 선행 실험을 찾지 못함** (단정은 불가: 비공개 연구·내부 자료 가능성) | 본 실험이 최소 단위 탐색 실험 역할 |

> 주의: Thunder-DeID의 595종 유형은 **개인식별정보 중심**이다. 방산 기술명 등은 법적으로 '개인정보'가 아니라
> '비밀·영업비밀·기술정보' 범주일 수 있으므로, 본 실험의 사전 항목을 **비식별 대상으로 볼지**
> (공개 판결문 마스킹 대상 여부) 사전에 정책 기준을 확정해야 한다. (§10 위험 참조)

## 3. 용어 정리

| 용어 | 본 보고서에서의 정의 |
|---|---|
| 최소 단위 | 사전 항목(term) 1개 = CSV 1행 |
| "10만 M" | 원 요청의 "M"은 데이터 용량(MB)이 아니라 **항목 수 10만 개**로 해석함. 1만~10만, 1만 간격 총 10단계. (확인 필요: ☐ 맞음 ☐ 다름 → ________) |
| 중첩 사전 | 10k ⊂ 20k ⊂ … ⊂ 100k. 규모 외 변수 통제 목적 |
| 시드 항목 | 공개 용어 기반 60개(`dict/defense_seed.csv`), 모든 단계에 포함 |
| 합성 항목 | 템플릿 조합으로 만든 가짜 항목 (`is_synthetic=1`). **실제 방산 정보 아님** |
| 저전력 프로파일 | 1코어 고정 + nice 19 + 가동률 50% (벤치 코드 기본값) |

## 4. 연구 질문 및 가설

| ID | 질문 | 가설 |
|---|---|---|
| RQ1 | 사전 규모가 커지면 처리 속도는 얼마나 떨어지는가? | Aho-Corasick 특성상 스캔 속도는 거의 일정, 적재시간·메모리는 선형 증가 |
| RQ2 | 저전력(1코어/50%) 환경에서 10만 항목 사전이 실무 속도를 만족하는가? | 판결문 1건(수만 자) 처리는 1초 미만 |
| RQ3 | 사전 규모 증가는 실제 판결문에서 오탐(특히 합성 항목 히트)을 늘리는가? | 합성 항목은 0건에 수렴, 일반명사형 시드 항목이 주 오탐원 |
| RQ4 | 사전 단독 vs SNU Thunder-DeID 단독 vs 결합(사전→모델)의 탐지 범위 차이는? | 방산 특화 항목에서 결합이 단독보다 재현율 상승 |

> RQ1~RQ3는 제공된 `benchmark.py`로 즉시 측정 가능. **RQ4는 Thunder-DeID 모델 추론과 정답 라벨(§7)이 추가로 필요**하며 본 키트의 범위를 넘는 2단계 작업이다.

## 8. 실험 절차

1. `python generate_dict.py` → 사전 10종 생성, `dict/manifest.csv` 확인
2. 판결문 ≥10건을 `samples/`에 배치 (파일 수·글자수를 §7.1에 기입)
3. 기준선: `python benchmark.py --profile normal --out results/normal.csv --dump-spans results/spans.jsonl`
4. 저전력: `python benchmark.py --profile lowpower --out results/lowpower.csv`
5. 각 프로파일 최소 3회 반복(스크립트 `--repeat 3`은 스캔 반복, 전체 재실행도 3회 권장) → 평균·표준편차
6. 결과 CSV의 값을 §9 표에 전사
7. (2단계) Thunder-DeID 추론 결과와 `spans.jsonl` 병합하여 RQ4 분석

측정 중 통제 사항: 다른 프로세스 최소화, 백신 실시간 검사 영향 기록, 노트북이면 AC 전원 여부 기록.

## 10. 분석 가이드 (결과 해석 시 점검)

- **RQ1**: 사전 규모 vs 적재시간·메모리를 선형 회귀. 스캔 속도 기울기가 0에 가까운지 확인.
- **RQ2**: 판결문 1건 처리 시간이 허용 기준(예: 1초)을 만족하는 최대 사전 규모 = ________
- **RQ3**: 합성 히트가 0이 아니면 템플릿 충돌 가능성, 시드 히트 중 "촬영", "브로커" 같은 **일반명사 항목**은 오탐 후보로 별도 분류.
- 사전 매칭은 부분 문자열 일치이므로 한국어 조사·어간 변형, 띄어쓰기 변형은 놓칠 수 있음 → 정규화(공백 제거) 변형 실험 후보.
- 절대 속도는 장비·엔진에 의존하므로 **프로파일 간 상대 비교**를 중심으로 서술.

## 12. 한계

1. 합성 항목은 의미적 다양성이 없어 **탐지 품질 평가를 대체하지 못한다**.
2. 시드 60개는 공개 용어 기반의 예시이며 실제 방산안보수사 사전이 아니다.
3. 공개 판례는 이미 비식별되어 있어 PII 탐지 정확도 평가에 제한이 있다.
4. 저전력 프로파일은 소프트웨어 제한(코어·우선순위·가동률)이며 실제 저전력 CPU의 클럭·캐시 특성을 완전히 재현하지 않는다.
5. 선행 실험 부재 판단은 공개 웹 검색 범위에 한정된다.
